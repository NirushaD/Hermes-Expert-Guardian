# Expert Guardian 0.8.0 — Explorer-style list and batch close

The left panel now uses a sortable details list with Incident, Chat, Status and Detected columns. Only open incidents appear. Click a row to view its individual workflow on the right. Use row checkboxes or Ctrl-click to select multiple incidents, Shift-click for a contiguous range in the current sorted/filtered order, and Ctrl+Shift-click to add a range. Select all applies to the visible filtered rows; Ctrl+A works while a row has focus, Space toggles selection, and arrow keys navigate rows. Search changes clear selection. Readable names remain separate from internal routing keys.

Close selected presents an explicit snapshot of up to 100 incidents with their chat names and a common closing reason. Confirm Close selected incidents to dismiss that exact batch without Expert review, execution or a verified-fix claim. Selection changes invalidate a pending confirmation; background refresh cannot add newly arrived incidents to it. Profile changes clear selections and confirmations. Checkbox selection does not open every incident or trigger draft generation for each selected record.

The server validates the complete selection and reason before attempting any closure, deduplicates exact chat/incident pairs and reuses the existing per-incident dismissal rules. Results report each success or refusal. Corrective attempts awaiting a result stay open, failed eligible selections remain marked, and other selected incidents can close successfully. Late reviews, pending drafts, retry blocks, permissions and review budgets retain their existing handling. A transport failure asks the user to refresh and inspect remaining open incidents rather than assuming success.

Validation on 15 November 2026: all 113 tests passed under installed Hermes Python. Frontend cases cover normal/Ctrl/Shift/checkbox selection, visible select-all, filters, confirmation cancellation, cross-chat closure, partial failures, refresh races and profile changes. Service/API tests cover batch bounds, whole-request validation, deduplication, exact session routing, confirmation and preservation of unselected/in-flight records. The isolated host SDK/native-approval probe and JavaScript syntax checks passed. The standard scanner rated the package safe with four low-severity loopback-address findings.

Live visual inspection remains unavailable because native/browser automation services are disconnected. Automated interaction checks use a React-hook harness. No real user incidents are batch-closed during validation or installation.

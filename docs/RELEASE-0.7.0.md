# Expert Guardian 0.7.0 — automatic local incident drafts

New detector incidents immediately receive a readable trigger explanation and provisional problem/outcome text. After the normal pre/post-tool hook decision, the configured local summary model drafts a problem statement and expected outcome in a bounded background queue. No Expert request is sent, no corrective operation is authorized, and Expert review budgets are unchanged. Detection and blocking do not wait for the model.

The worker uses transient, locally sanitized task and recent same-scope tool evidence. Existing incidents request generation when opened; a read-only query can supply limited task/tool evidence from that exact profile and chat around the incident's detection time. Missing evidence is explicitly uncertain. Raw task history, commands and tool responses are not persisted in Guardian or appended to an external packet. Generated fields pass sanitization/validation before storage. Local routing preserves literal-loopback, fixed-path, no-proxy/no-redirect/no-auth/no-cloud-fallback restrictions. The configured local server must itself serve a local model; Guardian cannot inspect its internal routing.

The review fields prefill when the draft arrives and remain editable. Polling does not overwrite user edits, explicit success criteria or an existing prepared packet/hash. Use generated draft deliberately replaces form edits. The tree uses a shortened problem statement to distinguish incidents. Later workflow stages also show the local draft. Pending, queued, generating, ready, unavailable and failed states are readable. Failure retains trigger-based text and offers explicit retry; no automatic retry loop occurs. Interrupted work can be retried after two minutes.

Two daemon workers, a 32-job queue and bounded transient context limit concurrency and memory. SQLite claims deduplicate across hook/backend processes. Closing an incident discards pending results without reopening it. Reset removes transient task context and workers cannot recreate deleted history. Plugin unload stops new work and returns unstarted jobs to pending. Sanitization is best effort; the user's exact reviewed packet remains the external approval boundary.

Validation: all 106 tests passed under the installed Hermes Python. New tests cover generation, queue bounds and deduplication, profile/session isolation, missing models, failures and retries, stale historical context, bounded read-only history access, draft prefilling, user-edit preservation, prepared-packet integrity, closure/deletion races and unload cleanup. The isolated Hermes SDK/native-approval probe passed with zero real tools or cloud calls. Python compilation and JavaScript syntax passed. Standard scan: safe, four low-severity literal-loopback-address findings.

A real call to the configured local model also passed using a public synthetic file-read incident. It generated both fields and stated uncertainty about the cause. Live visual acceptance remains separate from the React-hook interaction harness. Existing-user-incident generation is validated after installation without sending to Expert or executing a correction.
